= Software Bills of Materials (SBOMs)

Every OliveTin release publishes SBOMs so you can see exactly which third-party components ship in it.

== Release SBOM

Each GitHub release has two release assets, both describing the same contents:

* `OliveTin-<version>-sbom.cdx.json` - CycloneDX JSON
* `OliveTin-<version>-sbom.spdx.json` - SPDX JSON

One SBOM covers every archive, `.deb`, `.rpm`, `.apk` and MSI in the release, because they all contain the same two things:

* *The OliveTin service binary.* Go modules are read from the built binary's build info, so the list only includes modules that are actually compiled in. Build tools such as golangci-lint are left out.
* *The web UI.* The npm runtime dependencies come from `frontend/package-lock.json`. Development dependencies such as Vite and ESLint are left out.

The SBOM is generated by `var/sbom/generate.sh`, which GoReleaser runs during the release.

== Container image SBOMs

Container images get their SBOM as a BuildKit attestation, one for each platform (`linux/amd64`, `linux/arm64`). It covers the Fedora base image packages as well as the OliveTin binary. To view it:

[source,shell]
----
docker buildx imagetools inspect ghcr.io/olivetin/olivetin:<version> --format '{{ json .SBOM }}'
----

NOTE: The image attestation does not list the web UI's npm dependencies, because the image only contains the minified bundle. Use the release SBOM for those.

== Scanning for vulnerabilities

Any SBOM-aware scanner can read these files, for example:

[source,shell]
----
grype sbom:OliveTin-<version>-sbom.cdx.json
----
